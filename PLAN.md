# Data Safety Autofill — план

Веб-приложение, которое заполняет форму Google Play Data Safety по коду
Android-проекта. Соло, **40 Bobcoins**.

**Дедлайн: воскресенье 27 сентября, 21:00** по твоему времени (UTC+6).
Сдаём в 19:00 — два часа буфера на то, что платформа ляжет.

---

## Что строим

Перед публикацией в Google Play надо заполнить анкету Data Safety:
несколько десятков вопросов о том, какие данные приложение собирает,
передаёт ли третьим лицам, шифрует ли, можно ли их удалить. Заполняется
руками, час-полтора, и ошибиться легко — а за неточность приложение
снимают с публикации.

Главная ловушка: **сторонние библиотеки**. Firebase Analytics собирает
идентификаторы устройства, Crashlytics — логи и модель телефона, рекламные
SDK — рекламный ID. Разработчик про это забывает, потому что сам он этот
код не писал. Именно здесь инструмент даёт то, чего человек не видит.

Вход: манифест, список зависимостей, код. Выход: заполненная анкета, где
у каждого ответа есть обоснование и ссылка на конкретный файл и строку.

## Метрики

| Метрика | Как мерить |
| --- | --- |
| **Время** | ручное заполнение (фаза 0) против прогона инструмента |
| **Полнота** | сколько типов данных найдено против эталона |
| **Находки, которые человек пропустил** | типы из SDK, про которые ты сам не вспомнил |

Третья — самая сильная для питча. «Быстрее» говорят все; «нашло то, что
я бы не нашёл» — почти никто.

## Критерии судейства

1. **Application of Technology** — насколько полно и продуманно применён Bob
2. **Presentation** — ясность подачи
3. **Business Value** — практическая ценность
4. **Originality** — оригинальность решения

кода. Поэтому шесть часов на упаковку в воскресенье не сокращаются.
